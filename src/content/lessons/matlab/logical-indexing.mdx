You now know two ways to reach into an array: by position (`V(3)`) and by range
(`V(2:5)`). There's a third, and it's the one that makes MATLAB code look like
MATLAB.

## The idea

A comparison produces a logical array of the same size. That logical array can be
used **as an index**.

```matlab
V = [0.94 1.02 1.07 0.99 1.06];

mask = V > 1.05        % [0 0 1 0 1]  — logical
V(mask)                % [1.07 1.06]  — only where mask is true
V(V > 1.05)            % same thing, written directly
```

<Analogy>
  Positional indexing is **"give me items 3 and 5."**

  Logical indexing is **"give me every item that's over limit."** You don't need to
  know where they are, or how many there will be — you describe the property, and
  MATLAB finds them.

  It's the difference between a shopping list by shelf number and one by what you
  actually want.
</Analogy>

## Reading

```matlab
demand = [38 52 61 45 68 33 57];

demand(demand > 50)          % [52 61 68 57]
sum(demand > 50)             % 4      — how many
mean(demand(demand > 50))    % 59.5   — mean of just those
max(demand(demand < 50))     % 45     — largest below the threshold
```

That third line is worth reading twice: `demand > 50` selects the elements, and
`mean` averages only those. One expression, no loop, no temporary variable.

## Writing

Logical indexing works on the left of `=` too, which is where it gets powerful.

<CodeFile name="clean_data.m">
```matlab
V = [0.94 1.02 1.07 0.99 1.06];

% Clamp anything above 1.05 down to 1.05
V(V > 1.05) = 1.05;

% Replace impossible readings with NaN so they're excluded from statistics
measurements = [230 228 -99 231 -99 229];
measurements(measurements < 0) = NaN;

mean(measurements)              % NaN — NaN propagates
mean(measurements, 'omitnan')   % 229.5 — the answer you wanted
```
</CodeFile>

That `-99` sentinel is a real pattern in SCADA data, where a missing reading is
encoded as an impossible value. Converting it to `NaN` and using `'omitnan'` is the
honest way to handle it — the alternative, silently averaging in `-99`, produces a
wrong answer with no warning.

## Combining conditions

Use `&` and `|` — the **element-wise** operators — not `&&` and `||`.

```matlab
V = [0.94 1.02 1.07 0.99 1.06];

within  = V >= 0.95 & V <= 1.05;      % both conditions, element by element
outside = V < 0.95  | V > 1.05;       % either condition
outside = ~within;                     % same thing, negated
```

<Callout type="warning" title="&& and || do not work here">
  `V >= 0.95 && V <= 1.05` errors, because `&&` expects scalars. This is the mirror
  image of the conditionals lesson: `&&` for `if` conditions, `&` for arrays.

  A useful shorthand: **double for decisions, single for data.**
</Callout>

Watch the precedence — `&` binds tighter than `|`, just like `*` before `+`. When in
doubt, parenthesise:

```matlab
(V > 1.05 | V < 0.95) & is_load_bus       % clear
V > 1.05 | V < 0.95 & is_load_bus         % means something else entirely
```

## `find` — when you need positions

Logical indexing gives you *values*. `find` gives you *positions*.

```matlab
V = [0.94 1.02 1.07 0.99 1.06];

V(V > 1.05)          % [1.07 1.06]   — the values
find(V > 1.05)       % [3 5]         — where they are

find(V > 1.05, 1)    % 3             — just the first
[~, worst] = max(V); % 3             — position of the maximum
```

Prefer plain logical indexing when you want the data. Reach for `find` when the
*position* is the answer — "which bus is in violation?" needs the bus number, not
the voltage.

<Callout type="engineering">
  A complete limit check with no loop anywhere:

  ```matlab
  over  = V_pu > 1.05;
  under = V_pu < 0.95;

  fprintf('%d of %d buses in violation\n', sum(over | under), numel(V_pu));

  if any(over)
      fprintf('Overvoltage at buses: %s\n', mat2str(find(over)));
      fprintf('Worst: %.4f pu at bus %d\n', max(V_pu), find(V_pu == max(V_pu), 1));
  end
  ```

  Compare that with the nested loop you'd write in C. This is what people mean when
  they say MATLAB is expressive for engineering work.
</Callout>

## Filtering rows of a matrix

Data usually arrives as a matrix, one row per item. A logical vector selects rows.

```matlab
% Columns: bus number, voltage pu, load MW
data = [1  1.02  12.5;
        2  1.07   8.3;
        3  0.93  15.1;
        4  1.01   9.7];

V = data(:, 2);

violating = data(V > 1.05 | V < 0.95, :);   % whole rows, all columns
loaded    = data(data(:,3) > 10, :);        % rows where load exceeds 10 MW
```

The `:` in the column position keeps every column. This is the standard way to
filter a table of results — and it reads almost like the question you asked.

## Common mistakes

<Callout type="warning" title="Using && or || on arrays">
  Errors immediately. Double for decisions, single for data.
</Callout>

<Callout type="warning" title="Mask length must match">
  A logical index must be the same length as the dimension it indexes. Filtering a
  6-row matrix with a 5-element mask errors — usually a sign you built the mask from
  the wrong variable.
</Callout>

<Callout type="warning" title="Assuming the result keeps its shape">
  `V(V > 1.05)` returns only the matching elements, so it is almost always shorter
  than `V` — and for a matrix it comes back as a column regardless of the original
  orientation. If you need the shape preserved, assign into a copy instead:

  ```matlab
  V_clean = V;
  V_clean(V > 1.05) = NaN;    % same size as V
  ```
</Callout>

## Mini tasks

<Exercise n={1} kind="predict" title="What does each produce?">
  ```matlab
  x = [5 12 8 20 3 15];

  x(x > 10)
  find(x > 10)
  sum(x > 10)
  x(x > 10) = 0
  ```

  <Solution>
    - `x(x > 10)` → `[12 20 15]` — the values
    - `find(x > 10)` → `[2 4 6]` — their positions
    - `sum(x > 10)` → `3` — the count (logicals sum as 1s)
    - `x(x > 10) = 0` → `x` becomes `[5 0 8 0 3 0]`

    Three different questions — *what*, *where*, *how many* — and one assignment,
    all from the same comparison.
  </Solution>
</Exercise>

<Exercise n={2} kind="practice" title="Duration curve statistics">
  From a year of hourly voltages, report: how many hours were out of the 0.95–1.05
  range, what percentage of the year that is, and the worst value.

  <Solution>
    ```matlab
    function report_violations(V_pu)
    %REPORT_VIOLATIONS Summarise limit excursions in an hourly voltage series.

        over  = V_pu > 1.05;
        under = V_pu < 0.95;
        bad   = over | under;

        hours   = sum(bad);
        percent = 100 * hours / numel(V_pu);

        fprintf('Out of limits: %d hours (%.2f%% of the period)\n', hours, percent);
        fprintf('  overvoltage : %d hours, worst %.4f pu\n', sum(over),  max(V_pu));
        fprintf('  undervoltage: %d hours, worst %.4f pu\n', sum(under), min(V_pu));
    end
    ```

    Note what this makes possible. "Violations occur in 0.3% of annual hours" is a far
    more useful statement to a planner than "the worst hour is bad" — and it's three
    lines of logical indexing over a year of data.
  </Solution>
</Exercise>

<Exercise n={3} kind="debug" title="Why does this error?">
  ```matlab
  V = [1.02 1.07 0.98 1.06];
  if V > 0.95 && V < 1.05
      disp('all within limits');
  end
  ```

  <Solution>
    `&&` requires scalar operands, and `V > 0.95` is a 1×4 logical array. MATLAB
    errors with *Operands to the logical AND (&&) operator must be convertible to
    logical scalar values.*

    What was meant:

    ```matlab
    if all(V > 0.95 & V < 1.05)
        disp('all within limits');
    end
    ```

    Element-wise `&` combines the two arrays, then `all` reduces the result to the
    single true/false that `if` needs. Both changes are necessary — this is the
    conditionals lesson and this one meeting in the same line.
  </Solution>
</Exercise>

<KeyIdea>
  Logical indexing lets you say **what you want** instead of **where it is**. Most
  loops a beginner writes over data — filtering, counting, clamping, replacing — are
  one line of logical indexing.
</KeyIdea>
