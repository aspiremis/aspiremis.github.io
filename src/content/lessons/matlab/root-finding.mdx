Find $x$ such that $f(x) = 0$. It sounds like a narrow problem and it is the shape of
an enormous amount of engineering computation — including, once you rearrange it,
the load flow.

## Load flow is root finding

The power flow equations say that at every bus, calculated injection must equal
scheduled injection. Move everything to one side:

$$
f(\mathbf{x}) = \mathbf{P}_{calc}(\mathbf{x}) - \mathbf{P}_{sched} = \mathbf{0}
$$

That is $f(\mathbf{x}) = \mathbf{0}$ — root finding, in many variables at once. Every
method in this lesson generalises to that case, and the project at the end of the
module builds exactly that generalisation.

## Bisection — slow and unbreakable

If $f$ is continuous and $f(a)$ and $f(b)$ have opposite signs, a root lies between
them. Halve the interval, keep the half that still brackets, repeat.

<CodeFile name="bisection.m">
```matlab
function [root, iter] = bisection(f, a, b, tol, max_iter)
%BISECTION Find a root of f in [a,b] by interval halving.
%   Requires f(a) and f(b) to have opposite signs.

    arguments
        f        function_handle
        a        (1,1) double
        b        (1,1) double
        tol      (1,1) double = 1e-10
        max_iter (1,1) double = 200
    end

    fa = f(a);  fb = f(b);
    assert(sign(fa) ~= sign(fb), 'f(a) and f(b) must have opposite signs');

    for iter = 1:max_iter
        c  = (a + b) / 2;
        fc = f(c);

        if abs(fc) < tol || (b - a)/2 < tol
            root = c;
            return
        end

        if sign(fc) == sign(fa)
            a = c;  fa = fc;
        else
            b = c;
        end
    end

    root = (a + b) / 2;
    warning('Reached %d iterations without meeting tolerance', max_iter);
end
```
</CodeFile>

**Guaranteed to converge** if you start with a bracket. Also slow: each iteration
gains exactly one bit, so about **3.3 iterations per decimal digit**. Reaching 10⁻¹⁰
takes roughly 34 iterations, always.

## Newton-Raphson — fast and fragile

Use the derivative to jump to where the tangent line crosses zero:

$$
x_{k+1} = x_k - \frac{f(x_k)}{f'(x_k)}
$$

<CodeFile name="newton.m">
```matlab
function [root, iter, history] = newton(f, df, x0, tol, max_iter)
%NEWTON Find a root of f using Newton-Raphson.
%   DF is a function handle for the derivative.

    arguments
        f        function_handle
        df       function_handle
        x0       (1,1) double
        tol      (1,1) double = 1e-12
        max_iter (1,1) double = 50
    end

    x = x0;
    history = zeros(max_iter, 1);

    for iter = 1:max_iter
        fx = f(x);
        history(iter) = abs(fx);

        if abs(fx) < tol
            root = x;
            history = history(1:iter);
            return
        end

        dfx = df(x);
        if abs(dfx) < eps
            error('Derivative vanished at x = %.6g — Newton cannot proceed', x);
        end

        x = x - fx/dfx;
    end

    root = x;
    history = history(1:iter);
    warning('Did not converge in %d iterations (|f| = %.3e)', max_iter, abs(f(x)));
end
```
</CodeFile>

**Quadratic convergence** near the root: the number of correct digits roughly
*doubles* each iteration.

```text
10⁻¹  →  10⁻²  →  10⁻⁴  →  10⁻⁸  →  10⁻¹⁶
```

That's why a load flow converges in four or five iterations regardless of system size.

<Callout type="engineering">
  The **shape** of that sequence is the diagnostic from the debugging lesson. Print
  the mismatch every iteration and look at it:

  - Digits doubling → the derivative is correct.
  - Error falling by a constant factor → the derivative is **wrong**, and the code
    still converges, just linearly, to something that may be slightly off.

  A wrong Jacobian is the classic silent bug in a from-scratch load flow. The
  convergence rate exposes it in one glance.
</Callout>

## When Newton fails

Four distinct failure modes, all worth recognising:

**Zero derivative.** $f'(x_k) = 0$ makes the step infinite. Guard against it, as the
code above does.

**Poor starting point.** Newton is only guaranteed to converge *near* the root. From
far away it can diverge or wander. This is why load flow uses a **flat start** —
$|V| = 1.0$, $\delta = 0$ — which is close to the answer for a healthy system.

**Oscillation.** Some functions send Newton into a cycle, bouncing between two points
forever.

**Multiple roots.** Where $f$ has a repeated root, convergence degrades from quadratic
to linear.

```matlab
% Divergence from a bad start
f  = @(x) atan(x);
df = @(x) 1./(1 + x.^2);

newton(f, df, 0.5)     % converges to 0
newton(f, df, 2.0)     % diverges — the tangent overshoots further each time
```

## Secant — Newton without the derivative

Approximate $f'$ from the last two points:

$$
x_{k+1} = x_k - f(x_k)\,\frac{x_k - x_{k-1}}{f(x_k) - f(x_{k-1})}
$$

Convergence order about **1.618** — the golden ratio — so slower than Newton but
faster than bisection, and it needs no derivative. Useful when the derivative is
expensive or you simply don't have it.

## `fzero` — what you should usually call

```matlab
f = @(x) x.^3 - 2*x - 5;

fzero(f, 2)              % from a starting guess
fzero(f, [1 3])          % from a bracket — safer, guaranteed

opts = optimset('Display', 'iter', 'TolX', 1e-12);
[root, fval, flag] = fzero(f, [1 3], opts);
```

`fzero` implements **Brent's method**: it uses fast interpolation when that's
converging well and falls back to bisection when it isn't. You get near-Newton speed
with bisection's guarantee.

<Callout type="warning" title="Always check the exit flag">
  ```matlab
  [root, fval, flag] = fzero(f, x0);
  if flag <= 0
      error('fzero failed (flag %d)', flag);
  end
  ```
  `flag = 1` means success. Anything else means the answer should not be used, and
  MATLAB will not stop you using it.
</Callout>

## Common mistakes

<Callout type="warning" title="Not bracketing when you could">
  `fzero(f, [a b])` with a genuine sign change is guaranteed. `fzero(f, x0)` from a
  single guess is not — it searches for a bracket first and may fail.
</Callout>

<Callout type="warning" title="Testing only |f(x)| < tol">
  On a very flat function, $|f|$ can be tiny while $x$ is far from the root. Test the
  **step size** as well: `abs(x_new - x_old) < tol`.
</Callout>

<Callout type="warning" title="No iteration cap">
  Every iterative method needs one, and needs to report when it hits it.
</Callout>

<Callout type="warning" title="Hand-derived derivatives">
  A wrong derivative gives linear convergence, not failure — so it looks like it
  works. Check numerically: `(f(x+h) - f(x-h)) / (2*h)` with `h = 1e-6` should match
  your `df(x)` to several digits.
</Callout>

## Mini tasks

<Exercise n={1} kind="predict" title="How many iterations?">
  Starting from an error of 0.1, roughly how many iterations does each method need to
  reach 10⁻¹²?

  <Solution>
    - **Bisection:** one bit per iteration, ~3.3 per decimal digit. From 10⁻¹ to
      10⁻¹² is 11 digits ≈ **37 iterations**.
    - **Newton:** digits double each step — 10⁻¹ → 10⁻² → 10⁻⁴ → 10⁻⁸ → 10⁻¹⁶.
      About **4 iterations**.
    - **Secant:** order ~1.618, so roughly **6 iterations**.

    This is why load flow uses Newton despite the cost of forming a Jacobian. Four
    iterations of expensive work beats thirty-seven of cheap work — and the gap widens
    as the tolerance tightens.
  </Solution>
</Exercise>

<Exercise n={2} kind="practice" title="Solve a real power system equation">
  A load is fed through a line of impedance $Z = 0.05 + j0.20$ pu from a 1.0 pu
  source. Find the receiving-end voltage magnitude for a load of $P = 0.8$,
  $Q = 0.4$ pu.

  <Solution>
    The magnitude relation, from the standard two-bus derivation:

    $$|V|^4 + |V|^2\left(2(PR + QX) - |V_s|^2\right) + (P^2 + Q^2)(R^2 + X^2) = 0$$

    ```matlab
    R = 0.05;  X = 0.20;
    P = 0.8;   Q = 0.4;
    Vs = 1.0;

    f = @(V) V.^4 + V.^2 .* (2*(P*R + Q*X) - Vs^2) + (P^2 + Q^2)*(R^2 + X^2);

    % Two physical roots exist: the high-voltage (normal) and low-voltage
    % (collapsed) solutions. Bracket the one you want.
    [V_high, ~, flag] = fzero(f, [0.8 1.1]);
    assert(flag == 1, 'fzero failed');

    fprintf('Receiving-end voltage: %.4f pu\n', V_high);
    fprintf('Voltage drop:          %.2f%%\n', (Vs - V_high)/Vs * 100);
    ```

    The two roots are the entire point. The upper is the normal operating point; the
    lower is the collapsed solution on the far side of the P–V nose. As loading
    increases they approach each other, and at the nose they **merge** — which is
    exactly when the Jacobian becomes singular.

    Root finding and voltage stability are the same mathematics.
  </Solution>
</Exercise>

<Exercise n={3} kind="debug" title="Newton converges, but slowly">
  A student's Newton solver reaches tolerance in 40 iterations instead of 5, with the
  error falling by about a factor of 3 each time. What is wrong?

  <Solution>
    Almost certainly a **wrong derivative**.

    Newton with a correct derivative converges quadratically. Linear decay by a
    constant factor means the update direction is only approximately right — the
    method still creeps to the correct root, which is why it looks like it works.

    Check the derivative numerically:

    ```matlab
    x  = 1.5;
    h  = 1e-6;
    numerical = (f(x+h) - f(x-h)) / (2*h);
    analytic  = df(x);

    fprintf('numerical %.10f\nanalytic  %.10f\nrel diff  %.2e\n', ...
            numerical, analytic, abs(numerical-analytic)/abs(numerical));
    ```

    Agreement to 6+ digits means the derivative is right and the problem is elsewhere
    — a repeated root also degrades Newton to linear. Disagreement means you have your
    bug.

    This check takes thirty seconds and should be the first thing you do whenever a
    Newton method underperforms.
  </Solution>
</Exercise>

<KeyIdea>
  **Bisection is slow and certain; Newton is fast and fragile.** Newton's quadratic
  convergence is why load flow works at all — and the *rate* at which the error falls
  is the single best diagnostic you have for whether your Jacobian is correct.
</KeyIdea>
